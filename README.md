## a. Problem statement

Predict whether White can win with a king and rook against Black's king and pawn
on a7, with White to move. The target is `won` or `nowin`. Five classifiers are
compared on the same categorical board descriptors and held-out positions.

## b. Dataset description

- **UCI Chess (King-Rook vs. King-Pawn), KRKPA7**:
  [dataset source](https://archive.ics.uci.edu/dataset/22/chess+king+rook+vs+king+pawn).
- **3,196 rows and 36 categorical predictors**, plus target `outcome`.
- Class counts: **1,669 won**, **1,527 nowin**; no missing values or duplicate rows.
- Original [data](data/raw/kr-vs-kp.data) and [documentation](data/raw/kr-vs-kp.names)
  are preserved; the [dataset audit](data/DATASET_AUDIT.md) records schema checks.

The original documentation and raw data confirm 36 predictors despite inconsistent
feature metadata on the UCI landing page.

Repository. [DOI: 10.24432/C5DK5C](https://doi.org/10.24432/C5DK5C),

## d. Models used

Logistic Regression, Decision Tree, K-Nearest Neighbors, Multinomial Naive Bayes,
and RBF Support Vector Machine.

### Evaluation procedure

1. Map `nowin` to 0 and `won` to 1. Use a stratified 80/20 split with seed 42:
   **2,556 training rows and 640 held-out test rows**.
2. Fit one-hot encoding within each pipeline and training fold. The binary
   indicators require no additional scaling and satisfy Multinomial NB's
   nonnegative-input requirement.
3. Select parameters by **five-fold stratified training cross-validation F1**;
   refit each selected pipeline on the training set and save it under `model/`.
4. Select the overall winner by training CV F1, then evaluate all five saved
   pipelines on the same test set. The app never fits uploaded data.

`train.py` defines the grids; `results/*_cv.csv` stores all candidates. The rare
valid category `spcop=t` can be unseen during training, so the encoder ignores
unknown categories; separate validation rejects codes outside the audited domains.

KNN uses `algorithm="kd_tree"`, `metric="manhattan"` and `n_jobs=1`.
On one-hot inputs, Manhattan distance sums exact 0/1 differences. The explicit
search avoids the brute-force calculation paths implicated in the previous
inconsistency. Equally distant neighbors still exist: preserve training-row order,
the split and package versions, and verify results on each target environment.

| --- | --- |
| Logistic Regression | Test F1 0.9744; 7 false wins and 10 missed wins. Training F1 0.9767; CV F1 0.9685 +/- 0.0067. The small training/test F1 gap suggests limited overfitting on this split. Its additive linear boundary makes more test errors than the tree and RBF SVM, which can represent feature interactions. |
| Decision Tree | Test F1 0.9970; 0 false wins and 2 missed wins. Training F1 1.0000; CV F1 0.9952 +/- 0.0030. The unrestricted-depth tree fits the training labels perfectly, but its high CV and test F1 also support strong generalization on this split. Training perfection alone is not evidence of severe overfitting. The learned conjunctions of descriptor conditions suit this rule-based endgame task. |
| KNN | Test F1 0.9632; 18 false wins and 7 missed wins. Training F1 1.0000; CV F1 0.9596 +/- 0.0063. CV selected k=11 and distance weighting. With distance weighting, a training row is its own zero-distance neighbor; a perfect training score therefore does not establish generalization. The training/CV gap shows why held-out evaluation matters. Manhattan distance and an explicit KD-tree search are used; regression checks compare predictions and probabilities across calculation settings and batch sizes. |
| Naive Bayes | Test F1 0.8697; 52 false wins and 37 missed wins. Training F1 0.8907; CV F1 0.8858 +/- 0.0139. Both training and CV F1 are lower than for the other classifiers, suggesting limited model fit rather than only a large train/test overfitting gap. Its conditional-independence assumption may be restrictive for related board descriptors; this is a possible explanation, not an established cause. |
| Support Vector Machine | Test F1 0.9985; 1 false wins and 0 missed wins. Training F1 0.9996; CV F1 0.9966 +/- 0.0028. The RBF kernel allows nonlinear feature interactions. High training, CV and test F1 support the fit on these positions, while the high test MCC shows strong agreement across both labels. Its ranking is based on training CV, not on choosing the best held-out score. |
| Overall winner for this dataset | **Support Vector Machine**, selected by the highest mean training CV F1. Its advantage over Decision Tree is 0.0015; the test error counts are 1 versus 2. The runner-up is competitive, and this small difference does not establish statistical superiority. |

## Reproduce the project

The latest local run used **Python 3.14.4**. The earlier BITS lab run used
**Python 3.12.7**; the dev container now targets Python 3.12. The revised model
must also be verified in the lab environment. Install the pinned dependencies
from the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

To reproduce training and validate the project locally or on BITS Virtual Lab:

```bash
python scripts/audit_dataset.py
python train.py --environment local
python -m unittest discover -s tests -v
python -m pip check
```

On BITS Virtual Lab, use `python train.py --environment bits-lab` instead, then
run the same tests and dependency check. The environment flag records the
execution location; screenshots provide separate evidence.

Training overwrites saved models, splits, results, and the marked README section.
Keep the original data, row order, seed and dependencies unchanged. Versions,
source-row indices, source-code hashes and saved-model hashes are recorded in
`results/manifest.json`; selected and fixed parameters and detailed evaluations
are in `results/evaluation.json`.

After a final lab run, pull the saved artifacts locally and run the tests again.
Compare all six displayed KNN metrics on Streamlit with `results/metrics.csv`.
Capture training and test completion in the lab, replace the redacted evidence,
and rebuild the PDF. The existing screenshots remain evidence of the earlier run.

## Run and use the app

The committed models are ready to load; training is not required to start the app.

```bash
.venv/bin/python -m streamlit run app.py
```

Open **http://localhost:8501**, or use the
[deployed app](https://chess-endgame-lab-tushar.streamlit.app/).

1. Select the bundled 640-row test set or upload a labeled CSV, then choose a model.
2. View six metrics, the confusion matrix, classification report and ROC curve.
3. Use **Compare models** for all five models and **Positions** to inspect errors;
   download comparisons or predictions as CSV.

Uploads must be UTF-8 CSV with all 36 original predictors and target `outcome`
(`won`/`nowin`), up to **2 MB and 5,000 rows**. Column order may vary; use
`test_data.csv` as the example. Invalid schemas, categories or labels produce
readable errors. For single-class uploads, AUC displays **N/A** with an explanation.
Uploads stay in memory within the visitor's session; no training occurs in the app.
